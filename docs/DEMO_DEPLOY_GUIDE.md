# Demo & Deploy — регламент публикации AI-проектов

Версия документа: 0.1 (проект для проверки)

## 1. Назначение

Единая повторяемая процедура публикации демонстраций на существующем сайте-портфолио Glazounov AI Lab. Сайт на PHP-хостинге остаётся каталогом проектов; отдельный Demo Hub не создаётся.

## 2. Выбор формата демо

Формат выбирается для каждого проекта по его задачам и инфраструктуре:

- **Интерактивное демо на сохранённых результатах:** посетитель выбирает реальные тестовые примеры; серверный инференс не требуется. Обязательно обозначить, что результаты предварительно рассчитаны.
- **Живой веб-интерфейс:** ввод произвольного запроса и получение ответа от отдельного backend. Необходимы ограничения запросов, контроль расходов, обработка ошибок и защита от злоупотреблений.
- **Техническое API-демо:** Swagger/OpenAPI, когда важно показать интеграцию и API-контракт. Называть «Демо API», а не полноценным чатом.
- **Видео или скринкаст:** когда живой запуск технически или экономически нецелесообразен. Обозначить как запись.

Форматы можно комбинировать. Не внедрять VPS, Coolify и отдельный Demo Hub без подтверждённой необходимости.

## 3. Универсальная процедура

1. **Инвентаризация:** проверить репозиторий, ветку, версию, README, лицензии, исходные результаты, наличие работающего deploy; зафиксировать ограничения.
2. **Выбор демо:** определить, что посетитель сможет сделать, и честно указать, какие данные живые, а какие сохранённые.
3. **Подготовка:** выделить минимальные файлы и интерфейс; не публиковать токены, личные данные, секреты или тяжёлые модели без необходимости.
4. **Локальная проверка:** проверить интерфейс, сценарии ошибок, кодировки UTF-8, адаптивность, корректность ссылок и содержимого.
5. **Deploy:** для PHP/статических демо — существующий хостинг; для Python API — отдельный сервис (сначала проверять существующий Railway deploy). Проверить HTTPS, маршруты и логи.
6. **Интеграция:** добавить в карточку проекта конкретную кнопку «Демо», «Демо API» или «Видео», ведущую на проверенный URL; не использовать заглушки.
7. **Проверка изменений:** `git status -sb`, `git diff --check`, `git diff`; затем функциональная проверка. Коммит — только после подтверждения.
8. **Публикация:** отправить согласованные изменения в GitHub, вручную обновить сайт на PHP-хостинге, проверить публичную страницу и кнопку.
9. **Фиксация:** записать дату, версию, URL, формат демо, тесты, ограничения, сведения об инфраструктуре и способ отката.

## 4. Регламент Client Request Normalizer v1

**Решение:** интерактивное сравнение заранее сохранённых результатов Baseline и LoRA без запуска модели на сервере.

**Источник:** `Glazounov-AI/client-request-normalizer`, версия v1.0.0.

**Файлы данных:**
- `results/baseline_v1.jsonl`
- `results/lora_v1.jsonl`
- `data/test.jsonl`
- `results/baseline_metrics_v1.json`
- `results/lora_metrics_v1.json`
- `docs/data_schema.md`

**UI:** выбор одного из 15 тестовых запросов; исходный текст; Baseline и LoRA рядом; эталон; сравнение семи полей; индикаторы валидности JSON и схемы; сводные метрики.

**Обязательные пояснения:**
- Результаты получены заранее в локальном эксперименте; свободный ввод с живым инференсом недоступен.
- 120 синтетических примеров: 90 train, 15 validation, 15 test.
- Экспериментальный прототип, не производственная система.
- Модель не рассчитывает цены и не проверяет наличие товаров.
- Поддерживается одна основная позиция; часть ответов нарушает схему.

**Метрики (15 тестов):** JSON Validity 93,3% → 100%; Schema Validity 66,7% → 73,3%; Intent Accuracy 53,3% → 93,3%; Field Accuracy 39,1% → 85,7%; Exact Match 0% → 46,7%.

**Критерии готовности:** все 15 примеров корректно сопоставлены по идентичному тексту/порядку; ответы показаны без изменения; ошибки JSON отображаются как ошибки, а не исправляются молча; переключение работает; мобильная вёрстка проверена; никаких запросов к модели и ключей API; ссылка с портфолио проверена.

## 5. Текущее состояние других демо

- **RAG Assistant:** действующий Railway API `https://ragassistant-production-6923.up.railway.app/`; проверены `GET /health`, `POST /query`, Swagger `/docs`; на портфолио подключено «Демо API». Swagger не является пользовательским чатом.
- **AI IT Service Desk:** самостоятельный проект; нельзя выдавать RAG Assistant API за его backend. Формат демо и backend требуют отдельного решения.

## 7. Откат

Сохранить SHA предыдущего рабочего коммита и копию изменяемого PHP-файла на хостинге. При проблеме вернуть предыдущую проверенную версию сайта; для отдельного API использовать механизм rollback хостинг-провайдера, если он доступен.
